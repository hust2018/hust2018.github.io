# 3D 立体终端甲板与全站视觉优化设计

日期：2026-07-10

## 目标

在不改变简历内容结构、双语能力、静态导出和干净 PDF 渲染路径的前提下，为现有深色终端风格增加一套统一、克制且有记忆点的 3D 空间语言。

成功标准：

- 首屏第一眼具有清晰的 3D 层次，但姓名、职位、简介和状态仍是主要信息。
- 头像保留，并作为立体终端甲板中最前层的身份面板。
- 技能、经历、亮点、教育、联系和最新文章区块共享一致的景深、高光和悬浮反馈。
- 桌面、触屏、减少动态效果和打印场景均有明确的降级行为。
- 不引入 Three.js、React Three Fiber、WebGL 或其他大型 3D 依赖。
- `pnpm test` 和 `pnpm build` 通过，静态导出保持可用。

## 选定方向

采用 C「立体终端甲板」。它把现有终端视觉扩展到三维空间，通过前后叠放的身份卡、状态面板、细线、节点和阴影，形成微型工程工作台。相较于抽象能量球，该方向与工程师简历语义更一致；相较于单张全息身份卡，它也更容易自然延伸到全站卡片系统。

整体强度采用“平衡展示”：3D 是明显的首屏记忆点，但不覆盖正文、不抢夺阅读焦点，也不要求用户操作才能理解内容。

## 首屏设计

首屏继续使用当前左右两栏信息结构。

左栏保留：

- 终端提示符
- 姓名与 glitch 效果
- 职位打字机效果
- 简介、地点、状态和徽章

右栏由现有平面头像框升级为 `HeroDeck` 立体甲板：

1. 最前层为头像身份面板，继续使用 `/ljl-new.png`，并显示 `ID_0001`。
2. 中层为系统状态面板，使用少量与个人定位一致的装饰文本，例如 `AGENT STATUS: ONLINE`、`SYSTEM READY`。
3. 后层为终端遥测面板或空间框线，用于建立深度，不承载必须阅读的信息。
4. 青色为主高光，品红用于节点和局部强调，保持现有 CSS 变量体系。
5. 甲板外保留现有个人标语，但调整为与面板基线和宽度一致。

3D 装饰全部标记为非关键内容；读屏顺序仍以姓名、职位、简介和头像替代文本为主。

## 全站统一

首屏以下不建立新的大型 3D 场景，而是复用同一套“空间卡片”规则：

- Terminal：窗口边框增加内外层高光和轻微透视，悬停或聚焦时仅小幅抬升。
- Skills：技能行或分组增加渐变边框与前景高光，不改变现有信息密度。
- Experience：展开项作为可聚焦的空间面板，悬停与键盘焦点反馈一致。
- Highlights、Education、Contact、Latest Posts：共享轻量的层级阴影、边缘辉光和 `translateZ` 观感。
- Section Head：使用短距离深度线或光点串联区块，让页面从首屏向下保持同一视觉语言。

这些效果通过公共 CSS 类和变量实现，避免每个组件拥有一套不同的动效逻辑。

## 组件与职责

### `components/HeroDeck.tsx`

负责甲板的语义结构：头像身份面板、状态面板、遥测面板和装饰层。组件只接收语言或已经本地化的短标签，不读取简历以外的数据。

### `components/Hero.tsx`

继续负责首屏文案与整体两栏布局，使用 `HeroDeck` 替换当前的平面照片区域。它不直接处理指针数学或全局事件。

### `components/effects.tsx`

增加可复用的 `usePointerTilt` Hook。它负责浏览器指针事件、`requestAnimationFrame` 调度和 CSS 自定义属性写入；指针离开时将旋转值平滑归零。

### `lib/tilt.ts`

提供无浏览器依赖的 `calculateTilt` 纯函数，把容器内指针位置转换为受限的旋转值。该边界让角度方向、最大值和异常尺寸能够通过 Vitest 独立验证。

### `app/globals.css`

负责甲板的 3D 布局、空间卡片公共样式、响应式降级、打印隐藏和减少动态效果。统一使用已有颜色、阴影、尺寸和断点变量，不建立第二套主题。

## 交互与数据流

桌面指针在甲板容器内移动时，客户端组件读取元素边界，将指针相对位置归一化到 `-1...1`，再映射到最大约 4–6° 的 `rotateX/rotateY`。计算结果写入甲板根节点的 CSS 自定义属性，子面板根据各自深度使用不同的位移比例。

指针离开容器后，旋转值回到零。组件不把高频指针位置写入页面级 React state，避免触发整棵简历树重渲染。

全站普通卡片只使用 CSS 的 hover、focus-visible 和静态透视，不注册额外的全局指针监听。

## 响应式与可访问性

- 桌面且支持精确指针：启用甲板指针视差。
- 触屏或粗粒度指针：关闭指针跟随，保留幅度很小、周期较长的自动漂浮。
- `prefers-reduced-motion: reduce`：关闭指针视差、漂浮、扫描和非必要过渡，保持静态层级。
- 键盘：交互卡片的 `focus-visible` 样式与 hover 具有同等可见度。
- 读屏：装饰面板使用 `aria-hidden="true"`；头像具有具体、双语适配的替代文本。
- 移动端：甲板缩放并放在主文案之后，不制造横向滚动，不遮挡标语。
- 打印：甲板装饰层隐藏或扁平化，继续维持当前 WYSIWYG 打印规则；独立 PDF 生成脚本不改动。

## 性能边界

- 不新增运行时 3D 库。
- 动画只使用 `transform` 和 `opacity`，避免持续改变布局属性。
- 指针处理使用 `requestAnimationFrame` 合并更新，组件卸载时取消帧并移除监听。
- 3D 层数控制在首屏 3–4 个主要面板；不创建粒子系统或持续运行的 canvas。
- 不新增远程图片，继续复用现有本地头像资源。

## 测试与验证

实现采用测试驱动：

1. 为纯倾斜计算函数先写失败测试，覆盖中心点归零、四角方向、最大角度钳制和非法尺寸降级。
2. 实现最小计算逻辑使测试通过，再接入浏览器 Hook 与 CSS 变量。
3. 运行现有全部 Vitest 测试，确认博客和站点工具函数无回归。
4. 运行 `pnpm build`，验证 Next.js 静态导出、TypeScript 和所有路由构建成功。
5. 检查构建产物不包含 WebGL/Three.js 依赖，且 PDF/加密脚本未被更改。

## 明确不做

- 不重写简历文案或 `lib/data.ts`。
- 不改变博客信息架构或文章样式体系。
- 不加入音效、粒子背景、WebGL 模型或需要加载的 3D 资产。
- 不恢复主题切换器或旧的 IDE/Paper 变体。
- 不修改 `scripts/resume-html.mjs`、`pnpm pdf` 或 `pnpm encrypt` 的渲染结果。
